# 开源代码与组件使用情况说明

## 一、说明目的
本文档用于说明本项目在“智慧机场端平台、无人机端方案与视觉识别模块”中所使用的开源代码、开源组件与第三方技术栈情况，明确各组件的来源、用途、使用方式以及合规注意事项，便于在竞赛技术文档、答辩材料或项目备案文件中进行统一说明。

## 二、机场端工程开源代码与组件使用情况

### 1. 嵌入式固件侧
机场端嵌入式控制工程位于 `D:\Competition\code_main\qixiangzhan`，Keil 工程文件为 `MDK-ARM/qixiangzhan.uvprojx`。根据工程配置与目录结构，固件侧主要使用了以下开源或公开组件：

| 组件名称 | 来源/版本线索 | 主要用途 | 本项目使用方式 |
| --- | --- | --- | --- |
| STM32Cube HAL Driver | 本地目录 `Drivers/STM32H7xx_HAL_Driver` | 提供 STM32H743 外设抽象层驱动 | 用于 GPIO、ADC、UART、I2C、TIM、DMA 等底层外设驱动 |
| ARM CMSIS | 本地目录 `Drivers/CMSIS`，工程文件中引用 `CMSIS CORE` | 提供 Cortex-M7 内核标准接口、设备头文件与寄存器定义 | 用于启动、系统时钟、核心寄存器访问和芯片支持包 |
| STM32CubeMX 生成框架 | 本地存在 `qixiangzhan.ioc`、`Core/`、`Drivers/` | 生成基础工程框架和外设初始化代码 | 用于快速构建 H743 主控基础固件骨架 |

说明：
- 固件侧核心业务逻辑，如 L610 联网、气象数据采集、LCD 显示、继电器控制、协议封装、机场状态机等，主要位于 `HARDWARE/` 和 `Core/` 目录中，属于项目定制开发部分。
- 当前可确认工程中直接纳入的通用开源基础主要为 `STM32 HAL` 和 `CMSIS`，未在 `uvprojx` 中看到 `FreeRTOS`、`LwIP`、`FatFs` 等中间件被直接纳入编译。

### 2. 后端平台侧
机场端后端采用 `FastAPI + MySQL + MQTT` 技术栈，`backend/requirements.txt` 中可确认的第三方 Python 依赖如下：

| 组件名称 | 版本 | 主要用途 | 许可证信息 |
| --- | --- | --- | --- |
| FastAPI | 0.116.1 | 提供 Web API 服务框架 | MIT |
| Uvicorn | 0.35.0 | 提供 ASGI 服务运行环境 | BSD-3-Clause |
| SQLAlchemy | 2.0.43 | ORM 与数据库访问 | MIT |
| PyMySQL | 1.1.1 | MySQL 数据库连接 | MIT |
| cryptography | 45.0.7 | TLS/加密能力支撑 | Apache-2.0 OR BSD-3-Clause |
| PyJWT | 2.10.1 | JWT 认证令牌处理 | MIT |
| pydantic-settings | 2.10.1 | 配置管理 | MIT |
| paho-mqtt | 2.1.0 | MQTT 客户端通信 | EPL-2.0 OR BSD-3-Clause |

本项目中上述组件的用途主要包括：
- 使用 FastAPI、Uvicorn 构建机场端远程控制与状态服务接口；
- 使用 SQLAlchemy、PyMySQL 管理设备信息、历史记录、告警与用户数据；
- 使用 PyJWT 实现登录鉴权与接口访问控制；
- 使用 paho-mqtt 实现与 MQTT Broker 的状态上报与消息桥接；
- 使用 cryptography 与相关依赖支撑安全连接与认证链路。

### 3. Qt 桌面端/安卓端
根据 `qt-client/CMakeLists.txt` 与 `qt-client/README.md`，Qt 客户端主要使用了以下组件：

| 组件名称 | 来源/版本线索 | 主要用途 | 本项目使用方式 |
| --- | --- | --- | --- |
| Qt 6.5+ Quick | `find_package(Qt6 6.5 REQUIRED COMPONENTS Quick ...)` | 图形界面与 QML 前端 | 用于桌面端/安卓端统一 UI 构建 |
| Qt MQTT | `Qt6::Mqtt` | MQTT 连接与消息订阅 | 用于桌面工程模式下的本地 MQTT 联调 |
| Qt Network | `Qt6::Network` | HTTP/网络通信 | 用于 API 请求等网络能力 |
| Qt Sql | `Qt6::Sql` | SQLite 数据缓存 | 用于本地设备状态与消息缓存 |
| Qt SerialPort | `Qt6::SerialPort` | 串口调试 | 用于桌面端串口诊断与工程调试 |
| Qt WebSockets | `Qt6::WebSockets` | 实时状态接收 | 用于 WebSocket 实时更新 |
| QtKeychain | `qt-client/third_party/qtkeychain` | 凭据安全存储 | 用于保存 access token / refresh token 等敏感会话信息 |

其中：
- `QtKeychain` 已以 vendored 方式纳入项目 `third_party/qtkeychain`，其本地 `COPYING` 与 `ReadMe.md` 表明该组件采用 Modified BSD License。
- Qt 客户端的业务逻辑、QML 页面、设备状态管理、历史记录、告警中心和工程调试模块为本项目自研代码。

### 4. MQTT Broker / 中间件
项目说明文档中显示机场端平台使用 `EMQX` 作为 MQTT Broker/消息中间件，用于设备上线、状态回传、命令下发和实时状态分发。

需要特别说明：
- EMQX 目前上游主仓库已说明，自 `v5.9.0` 起采用 `BSL 1.1`（Business Source License）；
- 如果项目使用的是 EMQX Cloud 或新版本 EMQX，自用、教学、竞赛展示通常问题不大，但若进入正式商用部署，建议再次核对所用版本与授权要求；
- 如果只是将 EMQX 作为教学/竞赛环境中的消息中间件使用，通常可在“第三方平台组件”中说明其用途，而不必声称其为自主代码。

## 三、无人机端开源方案使用情况

无人机端方案参考并采用了 GitHub 仓库 `NEU-REAL/REAL_DRONE_400` 的公开方案与相关模块设计。根据该仓库 README 与源码目录，可确认其为东北大学 REAL 实验室公开的自主无人机组装与部署教程项目，包含硬件结构、飞控流程、感知与规划源码、启动脚本及部署资料。

### 1. 已识别的主要方案模块

| 模块/目录 | 来源线索 | 作用说明 |
| --- | --- | --- |
| `src/planner` | 仓库源码目录 | 无人机路径规划相关模块 |
| `src/planner/bspline_opt` | 仓库源码目录 | B-spline 轨迹优化相关模块 |
| `src/planner/path_searching` | 仓库源码目录 | 路径搜索相关模块 |
| `src/planner/plan_env` | 仓库源码目录 | 规划环境建模 |
| `src/planner/plan_manage` | 仓库源码目录 | 规划任务管理 |
| `src/planner/traj_utils` | 仓库源码目录 | 轨迹处理工具 |
| `src/planner/drone_detect` | 仓库源码目录 | 目标检测或感知相关接口模块 |
| `src/realflight_modules/px4ctrl` | 仓库源码目录 | PX4 控制相关模块 |
| `src/realflight_modules/mid360_fastlio/src` | 仓库源码目录 | 基于 MID-360 和 Fast-LIO 的定位建图相关模块 |
| `src/realflight_modules/realsense-ros` | 仓库源码目录 | RealSense ROS 驱动/感知相关模块 |

### 2. 在本项目中的使用定位
在本项目中，无人机端开源方案主要用于以下几个方面：
- 作为无人机本体搭建、飞控接线与部署流程的参考来源；
- 作为机载定位建图、PX4 控制、规划模块集成方式的参考或基础实现；
- 作为无人机端与智慧机场系统进行空地协同联调时的技术基础。

结合你当前项目语境，更稳妥的表述建议为：

> 无人机端自主飞行与规划部分参考并采用东北大学 REAL 实验室公开的 `REAL_DRONE_400` 无人机方案，对其中的飞控、定位建图、规划与传感器集成思路进行了学习、部署与适配，并结合本项目的智慧机场管控需求完成空地协同系统集成。

### 3. 许可与合规注意事项
这一部分非常重要。`REAL_DRONE_400` 仓库首页 README 明确写到：
- 项目“所涉及的所有代码、硬件设计全部开源”；
- 同时明确写有“严禁商用与转载，版权与最终解释权由东北大学REAL实验室所有”；
- 仓库根目录页面未看到标准 `LICENSE` 文件。

因此，建议你在正式材料里避免把该仓库描述为“可自由商用的标准开源许可证项目”。更准确的写法应该是：

> 本项目无人机端参考东北大学 REAL 实验室公开教学仓库 `REAL_DRONE_400` 的技术方案与实验流程，用于学习研究、竞赛验证和系统联调；如涉及代码再分发、商业落地或对外发布，需进一步征得原作者/实验室授权。

## 四、YOLOv8 视觉识别使用情况

本项目视觉识别部分使用了 `Ultralytics YOLOv8` 相关技术路线，用于无人机端目标检测、机场端视觉感知或业务场景中的图像识别任务。

### 1. 使用目的
YOLOv8 在本项目中的典型用途可表述为：
- 用于无人机端目标检测、场景识别或降落标识识别；
- 用于辅助视觉定位、任务目标识别与状态判断；
- 作为项目中“边缘视觉智能”能力的重要组成部分。

### 2. 推荐说明文字
可直接用于技术文档的表述如下：

> 本项目视觉识别模块采用 Ultralytics 发布的 YOLOv8 目标检测框架，对无人机任务场景中的目标对象、机场视觉标识或关键区域进行识别检测。项目在开源模型与框架基础上完成训练、部署与业务适配，用于支撑自主返场、目标识别与场景理解等功能。

### 3. 许可证注意事项
Ultralytics 官方仓库明确说明：
- 开源版本采用 `AGPL-3.0`；
- 若用于商业产品或商业部署，官方建议申请 `Ultralytics Enterprise License`。

因此建议你在材料中区分两种情况：
- 如果当前仅用于竞赛、科研和教学演示，可按开源使用情况说明；
- 如果未来项目要进入商业化产品、对外交付或闭源部署，需要进一步评估 AGPL-3.0 的传染性要求，必要时购买商业授权。
